# OC Studio — Agent Guide

Single source of truth for coding conventions. `CLAUDE.md` points here; if the two ever disagree, **this file wins** — update it rather than adding rules elsewhere.

## Product context

Personal web app for creating and editing fictional character profiles (OCs) for writing and roleplay. Single user, runs locally against a local PostgreSQL. UI language: **Vietnamese**.

## Scope rules (important)

- Work task by task. Do not implement features belonging to a later task.
- **Do not invent the domain model.** No character/profile/collection/template tables or types until the user provides the model.
- Do not add authentication, AI integration, or PDF export unless the task asks for it.
- Do not use mock data as if it were real data. Unimplemented controls must be visibly disabled (see `UnavailableAction`) or navigate somewhere meaningful — never a button that does nothing.
- Never drop, reset, or modify the user's existing database. Never guess DB credentials.

## Commands

```bash
pnpm dev | build | start
pnpm typecheck      # next typegen && tsc --noEmit
pnpm lint           # ESLint (flat config)
```

Before declaring work done: `pnpm typecheck && pnpm lint && pnpm test && pnpm build` must pass. Report real results; never claim a check passed without running it.

## Stack & versions

Next.js 16 (App Router, `cacheComponents`, `partialPrefetching`, `typedRoutes`, Turbopack), React 19, TypeScript strict, Tailwind CSS 4 (CSS-first config in `globals.css`, no `tailwind.config`), shadcn/ui (`radix-nova` style, `radix-ui` package, `cn` from the `cn` package), next-themes, lucide-react, Drizzle ORM + `pg`, Zod 4, Vitest 5 (jsdom), Playwright. Package manager: **pnpm only**.

## Architecture

- `src/app/` — routes only. Pages compose components; no business logic or DB queries inline beyond calling feature/db functions.
- `src/app/(dashboard)/` — everything inside the sidebar/topbar shell.
- `src/features/<feature>/` — feature modules (`components/`, and later `server/` for queries/actions, `schemas.ts` for Zod). Business logic lives here or in `src/db`, never in UI primitives.
- `src/components/ui/` — shadcn primitives generated by the CLI (`pnpm dlx shadcn@latest add <name>`). Keep edits minimal.
- `src/components/{layout,shared,providers}/` — app shell and cross-feature presentational components.
- `src/db/` — server-only. `getDb()` returns the Drizzle instance (lazy pool, reused across HMR). Schema in `src/db/schema/`, migrations in `src/db/migrations/` (generated; do not hand-edit after applying).
- `src/lib/env.ts` — server env validated with Zod. Add new env vars to the schema **and** `.env.example`.
- `src/i18n/vi.ts` — all user-facing strings. Do not hardcode Vietnamese copy in components; add keys here.
- `src/config/navigation.ts` — sidebar items (typed `Route` hrefs).
- Create folders/files only when they contain real code (no empty scaffolding).

## Next.js 16 conventions

- Cache Components is on. Any request-time data (DB, `cookies()`, `headers()`) must sit under a `<Suspense>` boundary; call `await connection()` before uncached DB reads that must not run at build time. Use `"use cache"` + `cacheLife()` only when caching is intended.
- `GET` route handlers are prerendered unless they touch request-time data — call `connection()` for live endpoints.
- Use generated `PageProps<"/route">` / `LayoutProps<"/route">` types (`next typegen`).
- Server-only modules start with `import "server-only"`. Never import `src/db/*` or `src/lib/env.ts` from a `"use client"` file.
- Prefer Server Components; add `"use client"` only for interactivity (theme, sidebar, forms).
- Mutations (later tasks): Server Actions with Zod validation for app-internal forms; Route Handlers for HTTP APIs.

## UI conventions

- Use semantic tokens only (`bg-background`, `text-muted-foreground`, `bg-accent`, `text-success`, `border-border`…). No raw hex/oklch or palette classes (`text-gray-500`) in components. New colors → add a token to `:root` **and** `.dark` in `globals.css`, then map it in `@theme inline`.
- Fonts: `font-sans` (Inter) for UI, `font-heading` (Lora) for titles.
- Reuse `PageHeader`, `EmptyState`, `UnavailableAction`. Pages use `space-y-6`/`space-y-8` rhythm inside the shell's `max-w-6xl` container.
- Every interactive element must be keyboard-reachable with a visible focus state; icon-only buttons need `aria-label`; decorative icons get `aria-hidden`.
- Must work at 360px width with no horizontal overflow. Sidebar: collapsible to icons on desktop (Ctrl/Cmd+B), Sheet drawer on mobile.
- Client-only state that affects markup (theme, media queries) must use `useSyncExternalStore` (`useIsClient`, `useIsMobile`) — the React Compiler lint rule forbids `setState` inside effects.

## Code style

- TypeScript strict, no `any` (lint error). Use `import type` / inline type imports.
- Prettier (100 cols, double quotes, trailing commas, Tailwind class sorting) — run `pnpm format`.
- Comments explain _why_, not _what_. Code identifiers and comments in English; UI copy in Vietnamese via `src/i18n`.
- Tests colocated as `*.test.ts(x)`. `server-only` is mocked in `vitest.setup.ts`.

## Environment

- `.env.local` holds secrets and is git-ignored; `.env.example` is the committed template.
- Windows dev machine; PostgreSQL 17 runs as a Windows service. `psql` is not on PATH.
