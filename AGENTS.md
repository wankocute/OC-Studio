# OC Studio — Agent Guide

Single source of truth for coding conventions. `CLAUDE.md` points here; if the two ever disagree, **this file wins** — update it rather than adding rules elsewhere.

## Product context

Personal web app for creating and editing fictional character profiles (OCs) for writing and roleplay. Single user, runs locally against a local PostgreSQL. UI language: **Vietnamese**.

## Scope rules (important)

- Work task by task. Do not implement features belonging to a later task.
- **The character domain model is defined and user-approved** (`docs/`, decisions Q1–Q12). Change it only through a task that asks for it, and keep the docs in sync. Do not invent models for areas not yet specified (collections, templates storage, AI generations).
- Do not add authentication, AI integration, or PDF export unless the task asks for it.
- Do not use mock data as if it were real data. Unimplemented controls must be visibly disabled (see `UnavailableAction`) or navigate somewhere meaningful — never a button that does nothing.
- Never drop, reset, or modify the user's existing database. Never guess DB credentials.

## Stack & versions

Next.js 16 (App Router, `cacheComponents`, `partialPrefetching`, `typedRoutes`, Turbopack), React 19, TypeScript strict, Tailwind CSS 4 (CSS-first config in `globals.css`, no `tailwind.config`), shadcn/ui (`radix-nova` style, `radix-ui` package, `cn` from the `cn` package), next-themes, lucide-react, Drizzle ORM + `pg`, Zod 4, Vitest 5 (jsdom), Playwright. Package manager: **pnpm only**.

## Architecture

- `src/app/` — routes only. Pages compose components; no business logic or DB queries inline beyond calling feature/db functions.
- `src/app/(dashboard)/` — everything inside the sidebar/topbar shell.
- `src/features/<feature>/` — feature modules (`components/`, and later `server/` for queries/actions, `schemas.ts` for Zod). Business logic lives here or in `src/db`, never in UI primitives.
- `src/components/ui/` — shadcn primitives generated by the CLI (`pnpm dlx shadcn@latest add <name>`). Keep edits minimal.
- `src/components/{layout,shared,providers}/` — app shell and cross-feature presentational components.
- `src/db/` — server-only. `getDb()` returns the Drizzle instance (lazy pool, reused across HMR). Schema in `src/db/schema/`, migrations in `src/db/migrations/` (generated; do not hand-edit after applying).
- `src/lib/env.ts` — server env validated with Zod. Add new env vars to the schema **and** `.env.example`.
- `src/i18n/vi.ts` — all user-facing strings. Do not hardcode Vietnamese copy in components; add keys here.
- `src/config/navigation.ts` — sidebar items (typed `Route` hrefs).
- Create folders/files only when they contain real code (no empty scaffolding).

## Character Fact domain

Spec: `docs/character-fact-schema.md`; decisions Q1–Q12 and open questions: `docs/character-domain-decisions.md`. Code: `src/features/characters/domain/` (imports only `zod` — enforced by a test). Current `schemaVersion`: **3**.

- `CharacterFacts` is the single source of truth. AI-edited content must never write back to it.
- `values` is a flat map `fieldKey → { state: "specified", value } | { state: "explicit_none" } | { state: "not_applicable" }`; **unspecified = key absent** (never stored). "None" is a state, never an empty list/string.
- Field keys, option codes, units and item ids are permanent technical ids — never derived from labels, never renamed or reused. Replace a field by marking it `deprecated` and adding a new key. Labels live in `labels.vi.ts`.
- Key prefixes encode scope: built-in `group.name`, character-scoped `custom.<id>` / `cg_<id>`, library-scoped `lib.<id>` / `lg_<id>`. Library definitions are passed in via `DefinitionContext` — never a global registry. Edits to a definition in use must pass `findBreakingChanges`.
- Every repeated element (list item, event, relationship…) has a stable `id`.
- Convert form input with `normalizeFactInput`, then validate with `parseCharacterFacts(input, context)`. Schemas never transform data. Stored v1 data goes through `migrateCharacterFacts` (never guess meaning).
- Anything sent to AI must go through `selectFactsForAi` (sensitive fields, items (`sensitiveItemIds`) and sub-fields excluded unless allowed for that request). Envelope metadata such as `sensitiveItemIds` must be preserved by every transformation.
- Presentation (basic/advanced, templates) never changes facts — see `presentation.ts`.
- Limits live in `constants.ts` (`LIMITS`); no magic numbers.
- Nesting limit: group → sub-group → field → leaf sub-field.
- Adding a built-in field: add it to `definitions.ts`, `labels.vi.ts` and the table in `docs/character-fact-schema.md` (tests check all three).
- Sample characters in `__tests__/fixtures/` are illustrative only — never seed them as real data.

## Persistence

Design: `docs/database-design.md`; migration workflow and backups: `docs/database-migrations.md`.

- All DB access goes through repositories (`src/features/*/server/*-repository.ts`, `import "server-only"`), created with `create…Repository(db)`. They throw only `RepositoryError` (`src/db/repository-errors.ts`) — never raw driver errors.
- `characters.display_name` and `characters.schema_version` are the only copies of `displayName` / `schemaVersion`; `characters.facts` (JSONB) holds the rest and a CHECK forbids duplicates.
- Every write validates facts with `parseCharacterFacts(facts, { library })` using all library definitions (including deprecated). Never strip or coerce stored JSON.
- `character_references` is a derived index rebuilt in the same transaction as the facts. Never write it directly.
- Updates and soft deletes require the expected `revision`; never overwrite on conflict. Keep the lock order documented in `docs/database-design.md` §9.
- Library field definitions: only compatible edits (`findBreakingChanges`); deprecate instead of delete; keys are never reused.
- DDL: `pnpm db:generate --name=…`, review the SQL, then `pnpm db:migrate`. Never `drizzle-kit push`, never destructive SQL on databases with data, back up first. Old JSON is migrated on read (in memory) and saved at the current version on the next update.
- Integration tests only touch databases whose name ends in `_test` (`src/test/test-database.ts` enforces it). Never run them against `DATABASE_URL`.
- No tables for profiles, AI generations or templates until those are specified.

## Server Actions & UI data flow

- Mutations are Server Actions in `src/features/*/actions.ts` (`"use server"`). Every action takes `unknown` inputs, validates them with Zod (ids are UUIDs), calls repositories, and returns `ActionResult` (`src/lib/action-result.ts`) — never throws to the client. Map errors with `failFromError`.
- After a mutation call `refresh()` (`next/cache`) so the current route re-renders in the same response. Skip it when the client navigates away (e.g. deleting from the detail page).
- Client Components may only `import type` from `@/lib/action-result` (it is server-only); use `@/lib/action-result-client` for helpers.
- Edits that carry a `revision` must handle `revision_conflict` without losing or silently resubmitting stale input (see `BasicInfoDialog`).
- Basic info edits go through `applyBasicInfo`: it rereads stored facts and changes only the six basic fields; fields in `explicit_none` / `not_applicable` / unsupported shapes are locked.
- List state (search, sort, filters, view) lives in the URL (`library-params.ts`).
- Images: never trust client MIME or file names — `detectImage` (file signature) decides the type; files go through `MediaStorage` (`src/features/media/server/storage.ts`) using generated keys only, and are served by `/media/[id]` (lookup by id). On a failed DB write the stored file is deleted; unused assets are cleaned up.
- Dynamic routes and anything reading request data (DB, `params`, `searchParams`, `usePathname`) sit inside `<Suspense>` (Cache Components).
- E2E tests must never use the developer database: Playwright starts its own server with `DATABASE_URL` pointing at `*_e2e_test` (`e2e/environment.ts`). Wait for hydration before interacting (see `openDialog` in `e2e/characters.spec.ts`).

## Next.js 16 conventions

- Cache Components is on. Any request-time data (DB, `cookies()`, `headers()`) must sit under a `<Suspense>` boundary; call `await connection()` before uncached DB reads that must not run at build time. Use `"use cache"` + `cacheLife()` only when caching is intended.
- `GET` route handlers are prerendered unless they touch request-time data — call `connection()` for live endpoints.
- Use generated `PageProps<"/route">` / `LayoutProps<"/route">` types (`next typegen`).
- Server-only modules start with `import "server-only"`. Never import `src/db/*` or `src/lib/env.ts` from a `"use client"` file.
- Prefer Server Components; add `"use client"` only for interactivity (theme, sidebar, forms).
- Mutations (later tasks): Server Actions with Zod validation for app-internal forms; Route Handlers for HTTP APIs.

## UI conventions

- Use semantic tokens only (`bg-background`, `text-muted-foreground`, `bg-accent`, `text-success`, `border-border`…). No raw hex/oklch or palette classes (`text-gray-500`) in components. New colors → add a token to `:root` **and** `.dark` in `globals.css`, then map it in `@theme inline`.
- Fonts: `font-sans` (Inter) for UI, `font-heading` (Lora) for titles.
- Reuse `PageHeader`, `EmptyState`, `UnavailableAction`. Pages use `space-y-6`/`space-y-8` rhythm inside the shell's `max-w-6xl` container.
- Every interactive element must be keyboard-reachable with a visible focus state; icon-only buttons need `aria-label`; decorative icons get `aria-hidden`.
- Must work at 360px width with no horizontal overflow. Sidebar: collapsible to icons on desktop (Ctrl/Cmd+B), Sheet drawer on mobile.
- Client-only state that affects markup (theme, media queries) must use `useSyncExternalStore` (`useIsClient`, `useIsMobile`) — the React Compiler lint rule forbids `setState` inside effects.

## Code style

- TypeScript strict, no `any` (lint error). Use `import type` / inline type imports.
- Prettier (100 cols, double quotes, trailing commas, Tailwind class sorting) — run `pnpm format`.
- Comments explain _why_, not _what_. Code identifiers and comments in English; UI copy in Vietnamese via `src/i18n`.
- Tests colocated as `*.test.ts(x)`. `server-only` is mocked in `vitest.setup.ts`.

## Environment

- Windows dev machine; PostgreSQL 17 runs as a Windows service. `psql` is not on PATH.
